# P0-2 Canonical Attempt Identity\n\nAn attempt is the immutable identity of one execution attempt. Counters remain operational metadata.\n\nCanonical relationship: task_id -> run_id -> attempt_id\n\nFields: attempt_number is ordinal; retry_of points to the immediately previous attempt; attempt_id is unique per attempt.\n\nRetry invariant: preserve mission/work/task/run, create a new attempt_id, increment attempt_number exactly one, and set retry_of to the previous attempt_id.\n\nThis reconciles native API and V3 retry behavior without changing either plane. P0-3 will map this identity to existing AEOS/API/V3 objects.\n\nGovernance boundary: identity-only; no execution, queue mutation, authority, merge, gate weakening, or history rewrite.
