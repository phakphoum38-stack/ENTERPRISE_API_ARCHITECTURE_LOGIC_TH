# Research OS — System Hardening & Autonomous Engineering Program

**Status:** PLANNED / NOT EXECUTED
**Program:** Identity + Evidence + Authority + Provenance
**Branch:** `docs/research-os-system-hardening-program`
**Canonical policy:** planning does not authorize workflow execution, merge, release, or install

## 1. Mission

Build a governed autonomous engineering foundation for Research OS in which Generator, Autobot, Friend Runtime, CI, Mission Control, and Release Authority have explicit boundaries and every important artifact/action can be traced to an exact source SHA.

The program exists to prevent stale-SHA verification, self-approval, authority escalation, generated-evidence fabrication, autonomous retry loops, artifact substitution, and provenance breaks.

## 2. Non-negotiable principles

1. Exact SHA identity is the primary binding key for verification.
2. `CAPTURED` never means `PASSED`.
3. `WAITING_FOR_SHA` is pending, not code failure.
4. Code/test/gate failures remain failures; waiting cannot hide them.
5. A fix creates a new SHA and requires new verification.
6. Evidence is immutable once consumed by downstream gates.
7. Stale or mismatched evidence is blocked.
8. Generator creates; it does not approve its own output.
9. Autobot diagnoses, repairs, and verifies; it does not release.
10. CI proves; Mission Control projects; Release Authority decides release.
11. Generated artifacts must be generated by their authoritative workflow, not fabricated manually.
12. Unknown, conflict, stale, missing, and mismatch states fail closed where authority is required.
13. No autonomous component may silently escalate its capabilities.
14. No workflow may self-dispatch without an explicit governed design.
15. No auto-merge is part of this program unless separately approved and governed.

## 5. The 46-item architecture backlog

### Identity

1. **SHA Arrival & Capture Gate** — wait for the intended SHA, then capture it as immutable pipeline identity.
2. **Exact SHA Binding** — every downstream gate binds to the captured SHA.
3. **SHA Lineage** — source/generated/fix/test/build/package/install relationships remain traceable.
4. **Immutable Verification Record** — captured identity cannot be rewritten mid-pipeline.
5. **Bounded Retry** — waiting for identity has a finite retry budget.

### Generator / Autobot

6. **Generator Create Boundary** — Generator creates artifacts but cannot approve/release.
7. **Autobot Repair Boundary** — Autobot can inspect, diagnose, repair, commit, and verify within capability limits.
8. **Generation Manifest** — every generation records generator version, input SHA, outputs, hashes, and schema.
9. **Autobot Action Ledger** — every autonomous mutation is auditable.
10. **Repair Budget** — repeated repair attempts terminate deterministically.

### Failure intelligence

11. **Failure Classification** — distinguish code, test, dependency, environment, infrastructure, identity, evidence, policy, and provenance failures.
12. **Retry Policy** — retry only transient classes; hard integrity/policy failures stop.
13. **Circuit Breaker** — repeated anomalies halt automation.

### Security / authority

14. **Authority Manifest** — define what every component may and may not do.
15. **Capability Gate** — tools/actions require explicit capability and scope.
16. **Credential Boundary** — credentials never become source/evidence/UI payloads.
17. **External Access Boundary** — future web/MCP access gets SSRF, redirect, timeout, and destination controls.

### Build / release

18. **Build Identity Gate** — built EXE must match the governed source identity.
19. **Package Identity Gate** — packages/installers must derive from the verified build.
20. **Installed Release Provenance Gate** — installed artifacts must trace back to governed source/build/package.
21. **Four-EXE Isolation** — each user receives only its intended EXE identity.

### Evidence

22. **Evidence Schema Registry** — versioned machine-readable evidence contracts.
23. **Evidence Self-Validation** — evidence must validate before consumption.
24. **Evidence Conflict Detection** — contradictory authority-relevant evidence blocks the chain.
25. **Evidence Freshness** — stale records cannot be silently reused.
26. **Evidence Provenance Chain** — producer, input, output, run, and result are traceable.

### Mission Control

27. **Read-only Unified Snapshot** — canonical aggregation without execution authority.
28. **Read-only UI Projection** — projection consumes the canonical snapshot only.
29. **Desktop Surface** — safe bounded rendering of the projection.

### Runtime

30. **Friend Runtime lifecycle** — intent, plan, policy, capability, tool, result, evidence.
31. **Approval Gate** — risky actions require the governed approval path.
32. **Computer Use Sandbox** — future browser/desktop control is bounded and observable.

### Learning

33. **Core Skills immutability** — self-learning cannot mutate core skills.
34. **Learned Skill lifecycle** — candidate, sandbox, test, evidence, confidence, promotion.
35. **Skill Provenance** — every promoted skill has traceable origin and validation.

### Automation / observability

36. **Workflow Intelligence boundary** — observe lifecycle without creating uncontrolled loops.
37. **Generate Orchestrator boundary** — coordinate generation, not release authority.
38. **Workflow Dependency Graph** — make workflow ordering and SHA relationships explicit.
39. **No Hidden Work** — autonomous claims require observable commits/artifacts/evidence.
40. **Run Correlation ID** — correlate generator, Autobot, CI, evidence, build, install, and release.
41. **Audit Log** — privileged actions record who/what/when/why/input/output/result.
42. **Health Model** — component health is explicit; UNKNOWN never becomes PASS.

### Safety / governance

43. **Fail Closed** — malformed, missing, stale, conflicting, or mismatched authority evidence blocks.
44. **No Self-Approval** — no agent can turn its own evidence into approval.
45. **No Authority Escalation** — capabilities cannot silently expand from read to write/approve/release.
46. **Research OS Constitution** — the above invariants become a governed architecture contract and validator target.

## 7. Gate semantics

```text
WAITING_FOR_SHA     = identity not available yet
CAPTURED            = identity recorded; NOT a pass result
VERIFYING           = validation in progress
PASSED              = the relevant validation actually passed
FAILED              = validation actually failed
STALE               = evidence is too old or bound to an obsolete identity
SHA_MISMATCH        = expected/observed identity differs
CONFLICT            = authority-relevant evidence contradicts
BLOCKED             = policy or integrity prevents continuation
TIMEOUT             = bounded wait/retry exhausted
```

`CAPTURED`, `VERIFIED`, or `READY_FOR_FINAL_GATE` must never be interpreted as release approval unless the authoritative release contract explicitly says so.

## 8. SHA transition rule

A code change invalidates verification derived from the previous source identity.

```text
SHA-A
  | analyze FAIL
  v
AUTOBOT FIX
  |
  v
SHA-B
  |
  +--> NEW CAPTURE
  +--> NEW ANALYZE
  +--> NEW TEST
  +--> NEW EVIDENCE
```

No result from SHA-A may silently certify SHA-B.

## 9. Autonomous action policy

Autobot may:

- read repository files and CI evidence;
- diagnose failures;
- modify permitted branch files;
- create commits when explicitly capability-enabled;
- request/observe new verification through governed workflow triggers.

Autobot may not by default:

- approve itself;
- merge protected changes;
- release software;
- install software as release authority;
- rewrite evidence to hide failure;
- bypass a required gate;
- escalate capability silently;
- create an unbounded retry loop.

Generator may create governed artifacts but may not declare its own output authoritative.

## 10. Generated artifact policy

Generated evidence and release artifacts are produced by their authoritative workflows. Planning documents may specify expected schemas and checks but are never substitutes for generated evidence.
