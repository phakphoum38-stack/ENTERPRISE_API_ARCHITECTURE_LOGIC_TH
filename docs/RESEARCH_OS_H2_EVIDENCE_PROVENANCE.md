# Research OS H2 — Evidence / Provenance

**Status:** IMPLEMENTATION DRAFT — verification required
**Base:** `feat/h1-generator-autobot-boundary`

## Purpose

Provide one bounded, immutable evidence contract that binds evidence to an exact source commit, producer, run correlation, and optional artifact digest. Evidence describes what happened; it never grants authority.

## Rules

1. Evidence records require a canonical 40-character lowercase source SHA.
2. Producer, schema, evidence type, correlation ID, and timestamps are bounded strings.
3. Artifact digests are SHA-256 when present.
4. Evidence payloads are bounded and reject secret-like keys and executable/dynamic content.
5. A provenance chain must be ordered and must not contain conflicting source identity.
6. A child evidence record must reference the same source SHA as its parent chain.
7. Freshness is explicit: malformed, stale, or missing identity evidence is not usable.
8. Evidence cannot carry approval, release, merge, dispatch, or authorization authority.
9. New source SHA means new evidence lineage; previous evidence cannot silently transfer to it.
10. The implementation is validation/model logic only; generated CI evidence remains generated by CI.

## Evidence lifecycle

```text
SOURCE SHA
   -> PRODUCER
   -> RUN / CORRELATION
   -> EVIDENCE RECORD
   -> VALIDATION
   -> PROVENANCE CHAIN
   -> AUTHORITATIVE CI / GATE
```

H2 does not replace existing CI evidence workflows. It gives downstream H3+ consumers a common fail-closed contract for evidence they receive.
