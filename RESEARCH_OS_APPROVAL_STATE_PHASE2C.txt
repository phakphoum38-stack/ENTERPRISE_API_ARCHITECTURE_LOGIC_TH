Research OS Friend — Approval State Phase 2C

Purpose
=======
Introduce an explicit owner-scoped approval state for side-effecting tools so discovery cannot become an execution bypass.

States
======
NOT_REQUIRED -> tool is classified safe by the current approval policy.
PENDING      -> side-effecting tool request exists but has no approval.
APPROVED     -> the exact owner/profile/session/request/tool tuple was approved.
DENIED       -> the exact tuple was denied; it cannot execute without a new request fingerprint.

Safety boundary
===============
- FriendOrchestrator remains the execution authority.
- OwnerPolicy remains the owner and explicit-tool authorization authority.
- Tool Search remains read-only and never executes tools.
- ApprovalGate only controls whether an already-authorized explicit tool may execute.
- Approval is bound to a request fingerprint, so changing request text creates a new approval identity.
- No credentials, hidden reasoning, or tool outputs are persisted by this phase.
- Approval state is currently in-process; durable approval history is a separate future increment.
